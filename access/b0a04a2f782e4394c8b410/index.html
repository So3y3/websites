COPY RULES

GitHub to Vercel in seven steps

  1. Create a GitHub account and a public repository.
  2. Create a Vercel account via Continue with GitHub.
  3. Add New Project, import the repo, click Deploy. No build settings for static HTML.
  4. Add your custom domain under Settings, then Domains.
  5. At your registrar add an A record (Host @, Value 76.76.21.21) and a CNAME (Host www, Value cname.vercel-dns.com).
  6. Wait 10 to 30 minutes. Vercel shows a green tick when it is live.
  7. Every future GitHub push auto-deploys.

part 3 · speed

Performance

Images are the number one cause of slow pages. Compress everything before you commit it.

Image compression (Python, Pillow)
# Compress JPG hero photo (target < 60 KB)
from PIL import Image
img = Image.open("photo.jpg")
img.save("photo.jpg", "JPEG", quality=72, optimize=True)

# Compress PNG logo / accreditation (target < 15 KB)
img = Image.open("logo.png").convert("RGBA")
img = img.quantize(colors=64, method=2)
img.save("logo.png", optimize=True)

Defer Google Fonts

A normal stylesheet link blocks rendering. Use the preload and onload pattern.

HTML head
<!-- In <head> -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="preload" as="style"
  href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600&display=swap"
  onload="this.onload=null;this.rel='stylesheet'">
<noscript>
  <link rel="stylesheet"
    href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600&display=swap">
</noscript>

Lazy loading and layout shift

HTML
<!-- loading=lazy on all images below the fold -->
<!-- Always include width and height to prevent layout shift (CLS) -->
<img src="photo.jpg" loading="lazy" alt="description" width="600" height="400">

llms.txt

A plain-text markdown file at the site root, written for language models. Keep it under a page.

  • One line: what the business is and does.
  • Pricing, stated plainly. For example: 199 pounds flat, no monthly fees.
  • Who it serves and what is included.
  • A notes-for-AI section naming the exact queries you want to be associated with.

If location is irrelevant, say so in llms.txt: work is remote by email, video and WhatsApp, location is never a barrier, and the audience is every English-speaking market.

FAQPage JSON-LD

part 5b · no more bots

Form spam protection, no captcha

Public forms attract bots within days. Spam reaches your inbox, and every bot submission burns Formspree free-tier quota (50 a month). One wave can lock out real clients for the rest of the month.

  1. Formspree _gotcha honeypot. Filled hidden field means Formspree discards it without counting it against your quota.
  2. Client-side guard. If the field is filled, show the success card and send nothing. The bot believes it worked.
  3. Time trap. Block any submit within 6 seconds of page load. Bots submit instantly, people just press send again.
HTML (inside the form, before the visible fields)
<input type="text" name="_gotcha" class="hp-field"
       tabindex="-1" autocomplete="off" aria-hidden="true">

<!-- gentle note under the submit button -->
<p class="form-note" id="form-block-note" style="display:none;">
  Please take a moment to check your details,
  then press send again.</p>
CSS
.hp-field { position: absolute; left: -9999px; top: -9999px;
            width: 1px; height: 1px; opacity: 0; }
JavaScript (before the normal fetch submit)
var formOpenedAt = Date.now();
form.addEventListener("submit", function (e) {
  e.preventDefault();
  var gotcha = form.querySelector('[name="_gotcha"]');
  if (gotcha && gotcha.value) {              // a bot filled the trap
    form.style.display = "none";
    if (successBox) successBox.classList.add("show"); // fake success
    return;                                  // send NOTHING
  }
  if (Date.now() - formOpenedAt < 6000) {   // too fast
    blockNote.style.display = "block";
    setTimeout(function() {
      blockNote.style.display = "none"; }, 6000);
    return;
  }
  // ... normal fetch(form.action) submit to Formspree
});

Test all three paths with headless Playwright: a bot with the honeypot filled sends zero requests, an instant submit is blocked, a patient human submit goes through. Confirm PASS before launch.

  • Mark any spam that still gets through as spam in Formspree. It trains the filter and spam does not count toward your limit.
  • The limit resets monthly. If real enquiries push past 50, upgrade. That is a good problem.
  • Use a separate endpoint per form type so one flood cannot poison another form.

part 6 · local

Google Business Profile

Gets you onto Google Maps and into local search. The fastest route to local visibility for a service business.

  1. Always use an Incognito or Private window, so Google does not silently switch accounts.
  2. Go to business.google.com, Add your business. Search for the name first.
  3. Choose the primary category carefully: Life Coach, Business Coach and so on.
  4. Choose Service business, not Add location, to hide your home address.
  5. Add service areas at region and country level, not just one city.
  6. Add website, phone, services, hours and a description.
  7. Upload branded photos: profile or cover photo, service graphics, logo.

Video verification for home-based businesses

Film yourself stating your name and business name, your working environment, your website open on screen, the Business Profile dashboard while logged in, and any certifications.

Created on the wrong account?

Business Profile, Settings, Managers. Invite the correct email as Owner, accept on that account, then remove the wrong one.

part 8 · lessons

Patterns proven in later builds

Blog with dual post types

  • Write New Article: a full post written in the dashboard, published as a standalone /articles/ page.
  • Share a Link: a link-drop card for external publications. microlink.io fetches the title, publisher and teaser, so the piece is credited without duplicating content.
  • Categories are toggle chips, not checkboxes. Checkbox plus label styling is fragile.

Editor with live preview

  • A formatting toolbar above the body: Bold, Italic, H2, H3, Bullet, Link.
  • An Edit and Preview toggle that renders exactly as published and updates as you type.
  • Dashboard modal at 960px max-width, body textarea at 420px minimum height.

Publishing pipeline (GitHub Contents API)

  • On publish, push posts.json, the standalone /articles/{slug}.html page, and a generated 1200x630 OG image to /og/.
  • The sitemap updates itself in the same flow.
  • Admin sits behind an #admin hash, with a fine-grained GitHub token limited to that one repo. The token lives in sessionStorage and is never committed.

Bug fixes worth remembering

  • The success card must live outside the form element.
  • A generated page must contain exactly one html, head and body set.
  • Share buttons must point at the standalone article URL so social crawlers see the right OG tags. Use the Clipboard API with an execCommand fallback.

Migrations, analytics and testing

  • Replacing Wix or any legacy platform: add 301 redirects in vercel.json for every old URL and verify each one.
  • Analytics: Umami, deferred script in the head. One website ID per site.
  • Test every interactive or JS change with headless Playwright. It must show PASS before you call it done.

If the agent starts going in circles

Start a new chat, paste the system prompt again and give it the file. Long chats rot. Paste errors, never describe them, and ask for one change per message.
